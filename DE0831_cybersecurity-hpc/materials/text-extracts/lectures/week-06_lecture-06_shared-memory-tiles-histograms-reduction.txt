Race Condition
Two updates can overwrite each other
Initial counter = 0
Thread 1  read 0  0+1=1  write 1
Thread 2  read 0  0+1=1  write 1
Final counter = 1. Two contributions should have produced 2.
A race condition lets the result depend on the order of concurrent
operations.

Naive Histogram
One global counter per bin
function histogram_kernel!(hist, data, num_bins)
i = (blockIdx().x - 1) * blockDim().x + threadIdx().x
stride = blockDim().x * gridDim().x
while i <= length(data)
bin = clamp(floor(Int32, data[i] * num_bins) + 1, 1, num_bins)
CUDA.@atomic hist[bin] += Int32(1)
i += stride
end
return nothing
end
Correct: every increment lands, whatever the order
Skewed data: most values fall into a few bins, so every thread
contends on the same global addresses and the kernel serialises

Privatisation
One private histogram per block
Privatisation gives each block its own copy of the histogram in
shared memory, so threads contend only with their own block, and
the copies are merged once at the end.

Privatised Histogram: Zero and Count
1 function histogram_privatized!(hist, data, nbins)
2  local_hist = CuDynamicSharedArray(Int32, nbins)
3  tid = threadIdx().x
4  i = tid  # 1. zero the private bins
5  while i <= nbins
6  @inbounds local_hist[i] = Int32(0)
7  i += blockDim().x
8  end
9  sync_threads()
10  i = (blockIdx().x - 1) * blockDim().x + tid
11  stride = blockDim().x * gridDim().x
12  while i <= length(data)  # 2. count in shared memory
13  x = @inbounds data[i]
14  bin = clamp(floor(Int32, x * nbins) + 1, 1, nbins)
15  CUDA.atomic_add!(pointer(local_hist, bin), Int32(1))
16  i += stride
17  end
18  sync_threads()
