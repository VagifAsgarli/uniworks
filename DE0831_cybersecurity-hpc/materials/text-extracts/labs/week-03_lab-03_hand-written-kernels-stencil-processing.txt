Exercise 1: Vector Addition Step by Step
Start with one thread doing everything:
using CUDA
function add_one_thread!(c, a, b)
for i in 1:length(a)
@inbounds c[i] = a[i] + b[i]
end
return nothing
end
N = 1_000_000
a = CUDA.rand(Float32, N); b = CUDA.rand(Float32, N); c = similar(a)
@cuda threads=1 blocks=1 add_one_thread!(c, a, b)

This implementation is correct but has very low throughput because one GPU core performs one
million iterations. Measure it as the lower-performance reference case.

function add_threads!(c, a, b)

1024 threads, and one block occupies a single SM, leaving the

Effects of Omitting the Bounds Guard
N = 1000, threads = 256 → blocks = 4 → 1024 threads.
Threads 1001–1024 index past the end of the array.
With bounds checking on: a device-side error on the next
synchronisation.
With @inbounds: a silent write into unrelated device memory.
This is the GPU equivalent of a buffer overflow, and unlike on the
CPU, there is no guard page to catch it. compute-sanitizer finds it.

Stencil Definition
Each output element is a weighted combination of a fixed
neighbourhood of the input:
R
out[i] =  ∑ wk ⋅ in[i + k]
k=−R
R  is the radius; the window has 2R + 1 elements.
1D: moving average, FIR filter, edge detection along a signal.
2D: image convolution (lecture 9).
Stencils are the archetypal memory-bound with reuse kernel: each
input element is read 2R + 1 times by neighbouring threads, and
shared memory serves that reuse.

Exercise 3: Naive 1D Stencil
const RADIUS = 3
function stencil_naive!(out, in)
i = (blockIdx().x - 1) * blockDim().x + threadIdx().x
if RADIUS < i <= length(in) - RADIUS
acc = 0.0f0
for k in -RADIUS:RADIUS
acc += in[i + k]
end
out[i] = acc
end
return nothing
end
N = 10^7
in_d = CUDA.rand(Float32, N)
out_d = CUDA.zeros(Float32, N)
@cuda threads=256 blocks=cld(N,256) stencil_naive!(out_d, in_d)

Exercise 4: Shared Memory with Halos
A block of T threads needs T + 2*RADIUS input elements: its own tile
plus a halo of RADIUS on each side.
halo  tile (T elements)  halo
[ - - - ][ x x x x x x x x x x x x ][ - - - ]
Threads 1:T load their own element.
The first RADIUS threads additionally load the left halo.
The last RADIUS threads additionally load the right halo.
sync_threads(), then everybody computes from shared memory.

The Tiled Stencil Kernel
1 function stencil_shared!(out, in, ::Val{T}) where {T}
2  temp = CuStaticSharedArray(Float32, T + 2 * RADIUS)
3
4  tid = threadIdx().x
5  i  = (blockIdx().x - 1) * blockDim().x + tid
6  lid = tid + RADIUS  # index into the shared tile
7
8  n = length(in)
9  if i <= n
10  temp[lid] = in[i]
11  if tid <= RADIUS  # halos
12  temp[lid - RADIUS] = (i - RADIUS >= 1) ? in[i - RADIUS] : 0.0f0
13  temp[lid + T]  = (i + T <= n)  ? in[i + T]  : 0.0f0
14  end
15  end
16  sync_threads()
17
18  if RADIUS < i <= n - RADIUS
19  acc = 0.0f0
20  for k in -RADIUS:RADIUS
21  acc += temp[lid + k]

Exercise 5: A Deliberate Race
# In-place stencil: concurrent reads and writes to neighbouring elements
function stencil_racy!(A)
i = (blockIdx().x - 1) * blockDim().x + threadIdx().x
if 1 < i < length(A)
A[i] = (A[i-1] + A[i+1]) / 2.0f0
end
return nothing
end
A = CUDA.rand(Float32, 10_000)
results = map(1:10) do _
B = copy(A)
@cuda threads=256 blocks=cld(10_000,256) stencil_racy!(B)
CUDA.synchronize()
sum(Array(B))
end
println(results)  # the ten values will NOT all be equal

Security Implications of Race Conditions
A race that crashes is found in testing.
A race that shifts a floating-point sum by 10−6 passes testing and
reaches production.
In a detection pipeline, a non-deterministic feature vector means a
non-reproducible alert, and an incident report that cannot be
verified.
Any result you submit in this course must be reproducible across
runs. If it is not, you have a race, not a rounding difference.

Exercise 6: Sliding-Window Entropy
Kernel
In lab 2 you computed one entropy value for a whole file. Now compute one per window, a stencil
over byte counts.
1  # One block per window; 256 threads = 256 bins
2  function window_entropy!(H, bytes, ::Val{W}) where {W}
3  counts = CuStaticSharedArray(Int32, 256)
4  tid = threadIdx().x
5  counts[tid] = Int32(0)
6  sync_threads()
7
8  base = (blockIdx().x - 1) * W
9  j = tid
10  while j <= W && base + j <= length(bytes)
11  b = @inbounds bytes[base + j]
12  CUDA.atomic_add!(pointer(counts, Int(b) + 1), Int32(1))
13  j += blockDim().x
14  end
15  sync_threads()
16
17  # ... reduce -p*log2(p) over the 256 bins, thread 1 writes H[blockIdx().x]
18  return nothing
19  end
