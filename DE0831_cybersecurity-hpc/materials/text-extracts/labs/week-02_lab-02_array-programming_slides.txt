An array is a shelf of numbered boxes
• A hundred million boxes, in one long row, numbered from 1
• Each box holds one byte: a whole number from 0 to 255
– A byte can be a letter, a pixel, a bit of a packet. Today they are letters.
• The shelf on the CPU and the shelf on the GPU are two different shelves
– Copying between them takes real time. We measure it in part five.
• That is the entire data structure for today
7
One fast worker, or 2560 slow ones
CPU  GPU
• A handful of workers, each very fast  • 2560 workers on a T4, each slower
• Walks the shelf box by box  • Every worker stands at their own box
• Brilliant at 'it depends what was in the last box'  • Hopeless if boxes must wait for each other
• 100 M boxes = 100 M steps in a row  • 100 M boxes = a few thousand steps
Sources: [1], [4]  8
Broadcasting
One instruction, shouted once, applied to every box on the shelf.
• You do not tell the workers to line up, or which box each one takes
• You say what to do to a box. The machine works out the rest.
• In code this is one character: a dot
– xor.(payload, key) - the dot is the shouting
9
The other question: reduce the shelf to one number
• Broadcasting: a hundred million boxes in, a hundred million boxes out
• Reduction: a hundred million boxes in, one number out
– How many spaces? How many letters? What is the total?
• This one does need workers to talk to each other. It still parallelises.
• Everyone adds their number to their neighbour's, then half of us sit down
– A hundred million numbers, added in 27 rounds. Not 100 million.
10
Checkpoint - before we open anything
Which of these four can 2560 workers do at the same time?
• Add 5 to every box on the shelf
• Replace every box with the box next to it, plus itself
• Add up every box into one total
• Sort the shelf into order, smallest to largest
– Take two answers before you say anything.

What XOR does, and why it undoes itself
• XOR compares two numbers bit by bit and answers 'were these different?'
– Same bit gives 0. Different bits give 1. That is the whole rule.
• Scramble: byte XOR key gives nonsense
• Unscramble: nonsense XOR the same key gives the byte back
– Doing it twice with the same key returns you to where you started
• One operation for both directions. Which is why attackers like it.

20
Reading it word by word
• .== - ask every box: are you equal to this?
– .>= and .<= work the same way, for at-least and at-most
• UInt8(' ') - the byte number for the space character, which is 32
– Quotes around a single character give you a character, not text
• sum(...) - add up the whole shelf, get one number back
– On true/false, sum counts. It is the same operation.
21
The question that matters: is this English?
Written English is almost entirely letters and spaces. That is the detector.
function english_score(bytes)  # returns 0.0 to 1.0
lower = (bytes .>= UInt8('a')) .& (bytes .<= UInt8('z'))
upper = (bytes .>= UInt8('A')) .& (bytes .<= UInt8('Z'))
space = bytes .== UInt8(' ')
sum(lower .| upper .| space) / length(bytes)
end
english_score(d_plain)  # right key -> ~0.99  wrong key -> ~0.19

Checkpoint - why letters, and not just printable?
Why did we count letters and spaces, instead of the whole printable range?
• Printable is too generous: 37% of all byte values are printable
– Several wrong keys still look 'all printable'. It cannot pick the key.
• Letters and spaces are only ~27% of values: a much tighter target
• Even so, a high letter-score proves 'looks like language', not 'is true'
– A page of random letters scores high and means nothing

Part 4 · ~17 minutes
Nobody gives you the key
26
The situation, honestly
• A one-byte key has exactly 256 possible values. All of them.
– From 0 to 255. There is no 257th option and no clever maths needed.
• You already have a function that scores a guess: english_score
• So: decrypt 256 times, score 256 times, keep the best one
• That is 26 GB of work. On a laptop, minutes. Here, about half a second.
• This is called brute force, and against a one-byte key it always wins
Sources: [10]  27
Why 2560 workers help here twice over
• Inside one guess: 100 M bytes XOR'd at once, then reduced to one score
• Across guesses: each of the 256 is completely independent of the others
– Guess 40 does not need anything from guess 39
• Today we parallelise the inside and loop over the outside
– The loop over 256 runs on the CPU. It is 256 steps. Nobody cares.
• Loops are not banned. Loops over 100 M things are banned.
28
The loop that is allowed
Nine lines. Every one of them is something you have already run.
scores = zeros(Float64, 256)  # an empty shelf for the 256 answers
for k in 0:255
trial = xor.(d_payload, UInt8(k))  # decrypt with this guess
scores[k + 1] = english_score(trial)  # how English does it look?
end
best_key = argmax(scores) - 1  # 90, which is 0x5a
Sources: [3], [11]  29
The two off-by-one traps
• Julia counts from 1. Most languages you have heard of count from 0.
– Guess 0 goes in slot 1. Hence scores[k + 1].
– argmax gives a slot number, so subtract 1 to get back to a key.
• UInt8(k) converts the counter into a byte before XOR sees it
– Without it: an error about no matching method, which means a type mismatch
• If your recovered key is out by one, this slide is why

• A brute-force key search with an automated plaintext test

Part 5 · ~15 minutes
Two speed-ups, and only one is true
34
Why the obvious way to time it is wrong
The first thing everyone reaches for, and why it reports a fantasy.
@time xor.(d_payload, 0x5a)
#  0.000021 seconds  <- 21 microseconds. This is a lie.
# The GPU works in the background. @time measured you ASKING,
# not the GPU DOING. It clocked the phone call, not the journey.
@time CUDA.@sync xor.(d_payload, 0x5a)
#  0.002100 seconds  <- 2.1 ms. This is real.
Sources: [1], [3]  35
Measure it properly
Warm up once, then time. The first run includes compiling.
using BenchmarkTools
# the first call also COMPILES the code - throw it away
CUDA.@sync xor.(d_payload, 0x5a)
# now measure the steady state
@btime CUDA.@sync xor.($d_payload, 0x5a)

The result nobody expects
• Try the key search on a tiny file: 1000 bytes instead of 100 MB
• The CPU wins. Comfortably.
– Copying to the GPU and back costs more than the whole computation
• The GPU is not a faster computer. It is a wider one.
– Wide only pays when there is enough work to fill the width
• Small job, few workers needed, and you paid to wake up 2560 of them
